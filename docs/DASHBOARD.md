# 대시보드 기획

`web/index.html` 한 파일. 라이브러리 없이 브라우저에서 Supabase 를 직접 읽습니다.

---

## 무엇에 답하는 화면인가

대시보드는 "예쁜 숫자판"이 아니라 **질문에 답하는 도구**여야 합니다.
이 파이프라인을 쓰는 사람이 실제로 던지는 질문은 다섯 개입니다.

| # | 질문 | 화면에서 답하는 곳 |
|---|---|---|
| 1 | **지금 이 데이터 써도 되나?** | 맨 위 상태 배지 |
| 2 | 오늘 뭐가 바뀌었나? | 변화 요약 + 최근 변화 목록 |
| 3 | **이번 달 숫자가 적은 게 진짜 감소인가?** | 신고 지연 그래프 ★ |
| 4 | 수집이 건강한가? | 실행 이력 |
| 5 | 시장이 어떻게 움직이나 | 월별 추이 · 지역별 표 |

1번이 맨 위에 있는 이유는 기획서의 원칙 때문입니다 —
**`status != "ok"` 면 그 소스를 쓰지 않는다.** 다른 숫자를 보기 전에
이것부터 봐야 합니다.

---

## ★ 3번이 이 대시보드의 핵심입니다

실거래가는 계약일로부터 30일 이내 신고입니다. 그래서 이번 달 숫자는
항상 적게 나옵니다. 이걸 모르면 **"거래 급감"이라는 틀린 기사**가 나갑니다.

실측 예:

```
2026-08 을 8/19 에 재니  148건
2026-08 을 8/20 에 재니  163건    ← 하루 만에 15건 늘어남
```

그래서 대시보드는 **"같은 달을 여러 날에 잰 기록"** 을 그래프로 보여줍니다.
선이 계속 올라가고 있으면 "아직 채워지는 중"이라는 뜻입니다.

다른 대시보드에는 없는 화면인데, 이 프로젝트가 애초에 만들려던 게
이 시계열이라 가장 중요합니다.

---

## 화면 구성

```
┌──────────────────────────────────────────────────┐
│  상태 배지   ok / stale / quarantined / failed    │  ← 제일 먼저
│  마지막 성공 · 기준 시점 · 신선도                  │
├──────────────────────────────────────────────────┤
│  거래   해제   오늘 변화(+ - ~)   격리   연속실패  │  KPI 타일
├──────────────────────────────────────────────────┤
│  ★ 신고 지연 — 같은 달을 언제 쟀나                │  선 그래프
├──────────────────────────────────────────────────┤
│  월별 거래량 · 중앙가 추이                        │  막대 + 선
├──────────────────────────────────────────────────┤
│  지역별 (거래 · 중앙가 · 최고가)  │  최근 변화    │  표 2단
├──────────────────────────────────────────────────┤
│  수집 실행 이력                                   │  표
└──────────────────────────────────────────────────┘
```

## 만들 때 지킨 것

**라이브러리를 안 씁니다.**
차트는 인라인 SVG 로 그립니다. CDN 이 죽어도, 인터넷이 막힌 곳에서도
파일만 열면 뜹니다. 의존성이 없으니 몇 년 뒤에도 그대로 열립니다.

**읽기 전용 키만 씁니다.**
`sb_publishable_...` 는 RLS 로 `select` 만 허용된 키입니다. 이 파일이
공개돼도 데이터를 못 고칩니다. (실제로 확인했습니다 — INSERT 시도 시 `42501`)

**실패를 숨기지 않습니다.**
API 가 안 되면 빈 화면 대신 무엇이 왜 실패했는지 보여줍니다.
`status != "ok"` 면 배지가 빨갛게 바뀌고 경고문이 뜹니다.
**오래된 데이터가 틀린 데이터보다 낫다** 는 원칙이 화면에도 적용됩니다.

**숫자에 단위와 맥락을 붙입니다.**
`price_manwon` 은 만원 단위라 그대로 쓰면 오해합니다. 화면에는 "억"으로
환산해 보여주고, 집계에서는 **해제 거래를 항상 제외**합니다.

---

## 어디에 띄우나

| 방법 | 설명 |
|---|---|
| 파일 열기 | `web/index.html` 을 브라우저로 그냥 엽니다. 설치 불필요 |
| GitHub Pages | 저장소가 Public 이라 바로 서빙됩니다 |
| VPS | Caddy 에 경로 하나 추가하면 됩니다 |

어디서 열든 Supabase 를 직접 읽으므로 **항상 최신**입니다.

> **Swagger 는 웹서버가 필요합니다.** `file://` 로 열면 브라우저가 보안상
> `openapi.yaml` 을 못 읽습니다. GitHub Pages 주소를 쓰거나, `web/` 에서
> `python -m http.server 8000` 을 띄우세요. (대시보드는 파일로 열어도 됩니다 —
> 외부 파일을 안 읽으므로)

# 실거래가 조회 화면

`web/search.html`. 대시보드와 같은 방식입니다 — 라이브러리 없이 브라우저에서
Supabase 를 직접 읽습니다.

## 무엇을 할 수 있나

| | |
|---|---|
| 지역 | 시도 → 시군구 (전국 254개) |
| 기간 | 계약일 범위 |
| 단지 | 이름 일부만 써도 됩니다 (`ilike`) |
| 면적 | 전용 ㎡ 범위 |
| 가격 | 억 단위 범위 |
| 해제 거래 | 제외(기본) · 포함 · 해제된 것만 |

결과는 표로 나오고, 계약일·면적·거래가·㎡당 단가로 정렬할 수 있습니다.

## 이 화면이 조심하는 것들

### 1. 통계를 표본으로 내지 않는다

Supabase(PostgREST)는 **한 번에 1,000행만** 돌려줍니다. `limit=5000` 을
보내도 1,000행입니다. 이걸 모르고 한 번만 부르면, "최근 1,000건"의
중앙값이 화면에는 그냥 "중앙값"으로 찍힙니다.

실제로 서울 8개 구 3개월(2,789건)에서 이렇게 차이 났습니다.

| | 최근 1,000건 | 전체 2,789건 |
|---|---|---|
| 중앙값 | 12.68억 | **13.40억** |
| 최고가 | 105.00억 | **250.00억** |

최고가가 **145억** 틀렸습니다. 그래서 `Range` 헤더로 페이지를 넘겨
최대 1만 행까지 받습니다.

페이지를 넘길 때 정렬은 **유일**해야 합니다(`deal_date` + `key`).
`deal_date` 만으로 정렬하면 같은 날짜 행들의 순서가 페이지마다 달라져,
어떤 행은 두 번 오고 어떤 행은 아예 빠집니다.

### 2. 잘랐으면 잘랐다고 말한다

1만 행을 넘으면 요약값에 별표를 붙이고 "전체가 아니라 표본"이라고 씁니다.
조용히 자르면 잘린 결과를 전부인 줄 알고 씁니다.

### 3. 해제(취소) 거래를 요약에서 뺀다

안 빼면 취소된 신고가가 역대 최고가로 잡힙니다. 실측 2.1%가 해제분입니다.

단, "해제된 것만"을 고른 경우는 그 거래들로 요약을 냅니다. 거기서 또
취소분을 빼면 0건이 남아 `최저 Infinity억`이 나옵니다 (실제로 났던
버그입니다).

### 4. 없는 기간을 "거래 없음"으로 보여주지 않는다

DB 에는 최근 12개월만 있습니다. 그보다 과거를 조회하면 0건이 돌아오는데,
그건 "거래가 없었다"가 아니라 "여기 없다"입니다.

아카이브 `index.json` 을 읽어, 고른 기간이 아카이브 구간과 겹치면
조회 전에 경고를 띄웁니다.

### 5. 지역 목록을 화면에 적어 두지 않는다

`config/regions.yml` → `scripts/build_web_regions.py` → `web/regions.json`.

두 벌을 손으로 맞추면 행정구역 개편 때 어긋나고, 어긋난 쪽이 화면이면
"그 지역은 데이터가 없나 보다"로 보입니다.

**지역 목록을 고쳤으면 이걸 돌리세요:**

```bash
python scripts/build_web_regions.py
```

대시보드도 같은 파일을 읽습니다. 예전에는 서울 8개 구가 코드에 박혀
있어서, 전국으로 늘리면 나머지 246개가 `11110` 같은 숫자로만 보였을
것입니다.

# 지역 비교 화면

`web/compare.html` — "어디가 비싼가, 그리고 그게 어떻게 변해 왔나".

조회 화면(`search.html`)이 **한 지역의 거래 목록**을 보여 준다면, 이 화면은
**여러 지역을 나란히** 놓습니다. 목록이 아니라 요약을 봅니다.

## 무엇에 답하나

| 질문 | 어디서 |
|---|---|
| 이번 달 어디가 비싼가 | 시도 타일 지도 (색 = 값) |
| 그 시도 안에서는 어디가 | 오른쪽 시군구 표 (정렬 가능) |
| 강남과 송파는 3년간 어떻게 갈렸나 | 아래 겹쳐 보기 (최대 6개) |
| 지금 자료가 어디까지 들어와 있나 | 맨 위 배너 + 빗금 타일 |

## DB 를 안 씁니다

`data/series/{source}.json` **하나만** 읽습니다. GitHub 미러라 DB 가 꺼져
있어도 뜹니다. 실제로 지금(2026-08-21) Supabase 프로젝트가 정지돼 있어
`search.html` 은 못 뜨지만 이 화면은 뜹니다.

series 에는 시점(`as_of`)마다 시군구별 요약(거래량·중위가·최고가·중위면적)이
이미 들어 있습니다. 비교에 필요한 건 그게 전부라, 45 MB 짜리 `latest` 를
받을 이유가 없습니다.

## 지도를 타일로 그린 이유

시군구 254개 경계(GeoJSON)는 수 MB 입니다. 몇 백 KB 짜리 요약을 보려고 그걸
받는 건 배보다 배꼽입니다. 외부 지도 API 는 키가 필요해서, 키가 없거나
막히면 **지도만 조용히 안 뜨는 화면**이 됩니다.

이 화면이 답할 질문은 "어디가 비싼가" 지 "경계선이 어디까지인가" 가
아닙니다. 그래서 시도 17개를 실제 방위대로 배치한 타일 격자로 그립니다.
외부 요청이 0이고, 색을 못 읽는 사람도 타일 안에 적힌 숫자로 같은 걸
읽습니다.

## 이 화면이 조심하는 것들

### 1. 안 받은 곳을 "거래 없음"으로 칠하지 않는다

자료가 없는 시도는 빗금 + `자료 없음` 입니다. 0으로 칠하면 "그 동네는
거래가 없구나"로 읽힙니다. 지금은 서울 8개 구뿐이라 화면 대부분이
빗금입니다 — 그게 사실입니다.

### 2. 한 달을 여러 번 잰 것 중 마지막을 쓴다

같은 `as_of` 를 매일 다시 잽니다(신고가 늦게 들어오니까). 아무 점이나
쓰면 덜 찬 값이 섞여 "그 달은 거래가 적었다"가 됩니다. 그래서
`collected_at` 이 가장 나중인 점만 씁니다.

### 3. 최근 한두 달은 낮게 보인다고 먼저 말한다

2026-08 서울 161건 vs 2025-03 서울 3,907건. 급감이 아니라 신고 지연입니다.
선택한 달이 최근 두 달 안이면 그 문구가 자동으로 뜹니다.

### 4. 시도 가격이 근사치라고 밝힌다

중위값은 합칠 수 없습니다. 시도 타일의 가격은 **시군구 중위가들의
중앙값**이고, 화면에 그렇게 적어 뒀습니다. 거래량은 합이라 정확합니다.

### 5. 전남·광주가 한 칸인 이유를 적는다

실거래가 API 가 두 지역을 같은 `12xxx` 묶음으로 돌려줍니다. 화면에서
갑자기 한 칸으로 보이면 버그로 의심받으니, 왜인지 화면에 적었습니다.
