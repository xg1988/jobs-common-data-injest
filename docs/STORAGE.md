# 5년치를 어디에 담나

## 결론

| | 어디에 | 얼마나 | 비용 |
|---|---|---|---|
| **최근 12개월** | Supabase | 약 311 MB | 0원 (무료 500 MB) |
| **그 이전 전부** | 저장소의 아카이브 파일 | 5년치 약 50 MB | 0원 |
| 원본 응답 | 저장소 `data/raw/` (gzip) | 5년치 약 48 MB | 0원 |

**5년치를 전부 갖고, 돈은 안 듭니다.**

## 숫자가 어디서 나왔나

전부 실측입니다. 추정한 것은 지역당 월 거래 건수 하나뿐입니다.

| 값 | 크기 | 어떻게 쟀나 |
|---|---|---|
| DB 행 하나 | 621 B | 본체 382 + 인덱스 239, 2,850행 실측 |
| JSON 레코드 하나 | 457 B | latest 1.24 MB ÷ 2,850행 |
| gzip 압축비 | 24배 | raw 1,916 KB → 80 KB |
| 전국 시군구 | 254개 | API 직접 확인 (`config/regions.yml`) |
| 지역당 월 거래 | 약 175건 | 확인분 40,633 ÷ 221 |

전국 한 달 ≈ **43,750건**.

| 범위 | 레코드 | DB | 아카이브(gzip) |
|---|---|---|---|
| 전국 3개월 | 13만 | 78 MB | 2 MB |
| 전국 1년 | 53만 | 311 MB | 10 MB |
| 전국 3년 | 158만 | 933 MB | 29 MB |
| **전국 5년** | **263만** | 1,555 MB | **48 MB** |
| 전국 10년 | 525만 | 3,109 MB | 95 MB |

## 왜 전부 DB에 넣지 않나

Supabase 무료는 500 MB입니다. 전국이면 **19개월이면 꽉 찹니다.**

| 방법 | 5년 가능 | 비용 | 걸리는 점 |
|---|---|---|---|
| Supabase 무료만 | ✗ | 0원 | 19개월에서 멈춤 |
| Supabase Pro | ✓ | 월 $25 | 돈 |
| **12개월 DB + 아카이브 파일** | ✓ | **0원** | 과거 조회에 한 단계 필요 |

세 번째를 택했습니다. `ingest query`가 그 "한 단계"를 대신 해 주므로, 쓰는 쪽에서는 차이가 없습니다.

## 조회

기간만 주면 됩니다. DB에 있는지 파일에 있는지 몰라도 됩니다.

```bash
python -m ingest query --source molit_apt_trade --from 2022-01 --to 2026-08 --region 11680
```

자세한 건 [ARCHIVE.md](ARCHIVE.md)에 있습니다.

## 과거 5년을 채우는 법

```bash
python -m ingest backfill --source molit_apt_trade --from 2021-09 --to 2025-08 --archive
```

`--archive`를 붙이면 받은 달을 아카이브 파일로 바로 씁니다. DB를 거치지 않습니다 — 1.5 GB는 무료 한도에 안 들어가서, 넣었다 빼려고 하면 백필 도중에 멈춥니다.

**API 호출 15,240회** (254개 지역 × 60개월). 일일 한도가 10,000회라 **이틀에 나눠** 받아야 합니다. 요청당 약 1초(`backfill_delay: 1.0`)라 하루치가 4~5시간입니다.

```bash
python -m ingest backfill --source molit_apt_trade --from 2021-09 --to 2023-08 --archive
```

```bash
python -m ingest backfill --source molit_apt_trade --from 2023-09 --to 2025-08 --archive
```

API는 **2006-01**까지 있습니다. 5년보다 더 받고 싶으면 그만큼 날짜를 늘리면 됩니다. 저장 비용은 1년에 10 MB씩입니다.

## 데이터가 얼마나 확정적인가

계약일로부터 30일 안에 신고하게 되어 있어서, 최근 한두 달은 계속 늘어납니다. 그래서 매일 최근 3개월을 다시 조회합니다(`rolling_months: 3`).

12개월이 지난 달은 사실상 확정입니다. 그래서 그때 아카이브합니다.

다만 **해제(취소) 신고는 한참 뒤에도 들어옵니다.** 아카이브한 뒤에 그 달이 바뀌면 `evict`가 행 수 불일치를 잡아내고 멈춥니다. 그때는 다시 아카이브하면 됩니다.

## 한도에 언제 다시 부딪히나

DB에 12개월만 두면 약 311 MB로 고정됩니다. 무료 한도 500 MB의 62%입니다.

여유가 부족해지면 순서대로:

1. `--hot-months`를 6으로 줄입니다 (156 MB)
2. `mkt_apt_trade_event`를 정리합니다 (변경 이력, 계속 쌓입니다)
3. Supabase Pro로 올립니다 (8 GB, 월 $25)

아카이브 파일 쪽은 한도가 사실상 없습니다. 10년치가 95 MB입니다.
